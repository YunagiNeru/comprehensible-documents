選択原則

文書名だけで種別を決めない。読者が最終的に要求を承認するのか、設計を実装するのか、障害を復旧するのか、概念を学ぶのかを確認する。

同じHTML内に複数種別が必要でも、文書全体を分割しない。主要目的を一つ選び、副次目的を明示したセクションとして統合する。

種別と推奨構造

文書目的、正本、推奨順序
種別読者の課題正本単位推奨する順序
要求仕様何を満たせば承認できるか判断する。要求、制約、受入条件目的 → 範囲 → 用語 → 要求 → 非機能 → 受入 → 未確定 → 追跡
概要設計境界と主要構造を理解し、詳細化できるか判断する。設計決定、境界、主要フロー目的 → 文脈図 → 境界 → 構成 → フロー → セキュリティ → 運用 → 復旧 → 追跡
詳細設計実装可能な契約と例外を確認する。インターフェース、データ、状態、アルゴリズム前提 → 契約 → データ → 状態遷移 → 処理 → 例外 → 性能 → テスト観点
ADRなぜその決定を採用したか追跡する。一つの意思決定状態 → 文脈 → 決定 → 理由 → 代替案 → 影響 → 再検討条件
ランブック安全に同じ操作結果へ到達する。開始条件、操作、期待結果、停止条件事象 → 安全条件 → 前提 → 手順 → 期待結果 → 失敗時分岐 → ロールバック → エスカレーション
運用・セキュリティ責任、権限、監視、復旧を判断する。統制、責任境界、検知、対応資産 → アクター → 脅威・障害 → 統制 → 監視 → 対応 → 復旧 → 監査証跡
API・参照正しい値や契約を素早く検索する。定義、署名、フィールド、制約索引 → 共通規則 → 項目別仕様 → 例 → エラー → 互換性
調査・分析証拠から結論の妥当性を評価する。問い、観測、推論、結論問い → 方法 → 証拠 → 観測 → 解釈 → 反証 → 結論 → 限界
教育・解説概念を理解し、別の課題へ適用する。概念モデル、完成例、練習到達目標 → 前提知識 → モデル → 完成例 → 理由 → 練習 → 確認

複合文書の扱い

  • 主要目的を文書契約で一つ宣言する。
  • 副次目的は独立した見出しと正本IDで境界を示す。
  • 要求と設計を混在させる場合、要求を設計上の決定へ言い換えない。
  • 操作手順を含む場合、説明文と実行手順を視覚的・意味的に区別する。
  • 教育技法は教育セクションだけへ適用し、参照や運用の検索性を損なわない。

文書種別は見た目ではなく、読者が完了すべき課題で決める。
