Architecture Decision Record / ADR-0001

文書の正本を単一HTMLへ統合する

仕様、設計、運用の判断根拠を、人間とAIが同じ可視情報から確認できる自己完結HTMLとして管理する。

状態
承認済み
対象
技術文書の作成と改訂
対象外
アクセス制御が異なる情報
最終確認
2026-08-03

01 / Decision

設計判断

この記録が確定する内容と、適用条件を最初に示す。

DEC-001

正本と成果物の統合

承認済み
種別
決定
規範強度
必須
適用範囲
同じアクセス権で共有できる一つの文書目的

要求、決定、制約、理由、例外、検証方法を、一つの自己完結HTML内で管理する。

理由と適用条件

正本を一か所に置けば、読者は複数資料から正しい記述を再構築せずに済み、更新者は同じ規則の写しを同期する必要がない。

機密区分やアクセス制御が異なり、一つのファイルでは安全性が成立しない場合は、この決定をそのまま適用せず、分割の承認を別に得る。

02 / Context

判断の背景

文書の長さではなく、読者が情報を探し、結び付け、更新するための負担を問題にする。

分散した文書から生じる理解負債
負債観測できる兆候この判断による扱い
探索負債必要な条件が複数ファイルへ散らばり、位置を予測できない。索引、見出し、安定IDで同じHTML内の到達先を示す。
推論負債事実、決定、推奨、未確定の区別がない。種別、状態、規範強度、適用範囲を可視化する。
統合負債正本、理由、例外、証拠を読者が頭の中で結び直す。関連情報を同じレコードか明示的なID参照で接続する。
更新負債同じ決定の言い換えが残り、改訂後に内容が競合する。正本本文は一度だけ書き、他の箇所では参照する。

03 / Options

比較した選択肢

読み手の分離、成果物の分割、単一HTMLへの統合を比較した。

選択肢と判断
選択肢利点問題判断
人間用文書とAI用要約を分ける各読者向けに表現を最適化できる。正本が二つになり、更新後の一致を保証できない。不採用
章ごとにファイルを分ける一ファイルの長さを抑えられる。条件や例外の探索と統合を読者へ移す。長さだけを理由には採用しない
自己完結HTMLへ統合する正本、表示、索引、理由を一つに保てる。情報設計と改訂規律が必要になる。採用

04 / Map

一つの正本へ至る文書モデル

人間とAIは別の派生資料ではなく、同じ可視HTMLから正本レコードを参照する。

05 / Canonical Records

正本を維持する規則

決定を実装可能な制約、要求、禁止、推奨へ分解する。

CON-001

正本本文の一意性

承認済み
種別
制約

適用範囲
要求、決定、制約、禁止

同じ規範を概要、本文、表、図へ別の正本として複製しない。

理由と確認方法

一覧と図は正本IDを参照するビューとして扱い、正本本文を短縮した別規則を作らない。

06 / Verification

検証方法

機械監査、コールドリード、実画面確認を別の検証として扱う。

  1. 自己完結性を機械監査する

    外部CSS、JavaScript、壊れた内部リンク、正本レコードの不足、意味構造の欠落を検査する。

    成功条件：ERROR 0であり、すべての警告を判断済みである。

  2. HTML単体でコールドリードする

    作成時の会話とSkillを知らない読者が、目的、範囲、正本、例外、次の行動を推測せず特定できるか確認する。

    成功条件：重要な判断に外部説明が不要である。

  3. 対象画面幅で表示する

    デスクトップとモバイルで、固定レール、本文索引、表、図、長い見出し、展開要素を目視確認する。

    成功条件：欠け、重なり、ページ全体の横溢れがなく、意味の階層が保たれている。

07 / Consequences

影響と適用限界

この判断によって減る負担と、残る責任を区別する。

期待する影響

  • 人間とAIが同じ記述を根拠にできる。
  • 規範の重複が減り、改訂対象を正本IDから追跡できる。
  • HTML単体を移動しても、内容と視覚的な意味が失われない。

残る責任

  • 機械監査は意味の正しさや理解を保証しないため、人間によるコールドリードが必要である。
  • アクセス制御が異なる情報を一つに統合してはならない。
  • 安定IDがあっても、正本本文を複製すれば更新負債は再発する。

未確定事項：このADRの適用範囲には、現時点で未確定事項はない。アクセス制御との競合が生じた場合は、新しい判断記録を作成する。
